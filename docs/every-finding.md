detect, and `9` are not reported by an off the shelf automated
scanner at all. That second number is the argument for this repository
existing: on a closed platform, the findings that decide whether a
keyboard user can use the site are mostly the ones a scanner is silent
about.

## What each one means

### `page-lang-missing`

WCAG 3.1.1. Found by reading the page.

The html element carries no lang attribute, so a screen reader reads the page in the user default voice.

### `main-landmark-missing`

WCAG 1.3.1. Found by reading the page.

The page has no main landmark, so there is nothing for a skip link or a landmark shortcut to target.

### `skip-link-missing`

WCAG 2.4.1. Found by reading the page.

No link offers to skip past the repeated header. Neither platform emits one and neither has a setting for it.

### `skip-link-target-missing`

WCAG 2.4.1. Found by reading the page.

A skip link exists and resolves to nothing, or to an element that cannot take focus. Both look exactly like a working skip link.

### `control-unnamed`

WCAG 4.1.2. Found by reading the page.

An interactive control has no accessible name. Icon only header and gallery controls are the usual source.

### `image-control-unnamed`

WCAG 4.1.2. Found by reading the page.

A control whose only possible name is an image, and the image has no alt. This is the state a repair layer creates for itself when it clears a filename alt without asking what the image is doing.

### `alt-is-filename`

WCAG 1.1.1. Found by reading the page.

An image alt is the uploaded filename, which both editors prefill. It carries no information and is read out in full.

### `iframe-unnamed`

WCAG 4.1.2. Found by reading the page.

An embedded frame has no title, so it is announced only as a frame. Naming it is the whole of what the parent page can do.

### `link-text-generic`

WCAG 2.4.4. Found by reading the page.

A link name carries no purpose on its own. Summary blocks and blog grids produce a page of identical Read More links.

### `promoted-control-unreachable`

WCAG 2.1.1. Found by reading the page.

An element advertises a button role and has no tab stop, so it is announced as a control nobody can reach.

### `announcement-close-inert`

WCAG 4.1.2. Found by reading the page.

The announcement bar close control is unnamed, roleless or unreachable. It sits first in the tab order on every page of the site.

### `nav-focus-not-moved`

WCAG 2.4.3. Found by driving the page and watching what moves.

Opening the mobile overlay leaves focus behind it. Nothing in the markup distinguishes an overlay that moves focus from one that does not.

### `nav-focus-escapes`

WCAG 2.4.3. Found by driving the page and watching what moves.

Tabbing inside the open overlay walks out into the page underneath, which is still fully tabbable and invisible.

### `nav-escape-key-dead`

WCAG 2.1.2. Found by driving the page and watching what moves.

Escape does not close the open overlay, so a keyboard user who opens it has no documented way back.

### `promoted-control-key-dead`

WCAG 2.1.1. Found by driving the page and watching what moves.

An element has a button role and a tab stop and ignores Enter and Space. It announces an interaction it does not have, which is worse than being unreachable.

## Absence findings

These 3 report that something is not on the page at all, rather
than that something on the page is wrong:

- `page-lang-missing`
- `main-landmark-missing`
- `skip-link-missing`

They fire on an empty document, correctly, and that makes them useless as
evidence that a failing example demonstrates its own defect. A blank HTML
file would satisfy a test that only asked for "at least one finding".
`test/pairs.test.mjs` therefore requires every failing example to produce at
least one finding from outside this set, and runs every check against an
empty document to confirm that nothing outside it fires there.
