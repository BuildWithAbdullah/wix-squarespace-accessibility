Do not edit this file. CI fails if it drifts.

Each directory holds the same page twice: `fail.html` as the platform
emits it, and `pass.html` as it should be. `test/pairs.test.mjs` asks three
questions of every pair, and the third is the one that matters to anybody
pasting the bundle into a client site:

1. Does the failing page produce exactly the findings it claims?
2. Is the corrected page clean of them?
3. Does the shipped repair layer, injected into the failing page, earn the
   same grade as correcting the page at source would?

## What each pair proves

### 01-skip-link-stale-target

A skip link whose target the platform replaced.

- `skip-link-target-missing`, WCAG 2.4.1. A skip link exists and resolves to nothing, or to an element that cannot take focus. Both look exactly like a working skip link.

### 02-unnamed-icon-controls

Icon only header controls with no accessible name.

- `control-unnamed`, WCAG 4.1.2. An interactive control has no accessible name. Icon only header and gallery controls are the usual source.

### 03-filename-alt

Alt text prefilled with the uploaded filename.

- `alt-is-filename`, WCAG 1.1.1. An image alt is the uploaded filename, which both editors prefill. It carries no information and is read out in full.

**The repair does not clear this one, and that is the point.** One of the two filename alts is the only accessible name on a link. Clearing it would turn a 1.1.1 finding into a 2.4.4 and 4.1.2 one, so the rule refuses, marks the image and reports it. Nothing automatic can do better: no script knows where the link goes or what the picture shows. This finding is supposed to survive, and a human writing an alt in the editor is the only thing that clears it.

### 04-unnamed-iframe

Embedded frames with no title, including an empty one.

- `iframe-unnamed`, WCAG 4.1.2. An embedded frame has no title, so it is announced only as a frame. Naming it is the whole of what the parent page can do.

### 05-mobile-nav-focus

Mobile overlay that never takes focus and ignores Escape.

- `nav-focus-not-moved`, WCAG 2.4.3. Opening the mobile overlay leaves focus behind it. Nothing in the markup distinguishes an overlay that moves focus from one that does not.
- `nav-focus-escapes`, WCAG 2.4.3. Tabbing inside the open overlay walks out into the page underneath, which is still fully tabbable and invisible.
- `nav-escape-key-dead`, WCAG 2.1.2. Escape does not close the open overlay, so a keyboard user who opens it has no documented way back.

### 06-generic-link-text

Summary block where every link says the same thing.

- `link-text-generic`, WCAG 2.4.4. A link name carries no purpose on its own. Summary blocks and blog grids produce a page of identical Read More links.

### 07-gallery-controls

Lightbox controls with a button role and no button behaviour.

- `control-unnamed`, WCAG 4.1.2. An interactive control has no accessible name. Icon only header and gallery controls are the usual source.
- `promoted-control-unreachable`, WCAG 2.1.1. An element advertises a button role and has no tab stop, so it is announced as a control nobody can reach.
- `promoted-control-key-dead`, WCAG 2.1.1. An element has a button role and a tab stop and ignores Enter and Space. It announces an interaction it does not have, which is worse than being unreachable.

### 08-announcement-bar

Announcement bar close that is unnamed, roleless and unreachable.

- `announcement-close-inert`, WCAG 4.1.2. The announcement bar close control is unnamed, roleless or unreachable. It sits first in the tab order on every page of the site.
